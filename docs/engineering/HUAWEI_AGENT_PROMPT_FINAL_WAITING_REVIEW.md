## 二、研究目标和已有背景

研究对象是一个集群（GF网关＋XPYD，当前主要为3P3D），不是GB网关。目标是在吞吐提升或不下降的前提下改善全体请求P90 TTFT，P95为补充，并满足P90 TPOT约束。最终面向生产流量；AISBench闭环用于比较同并发尾延迟或相同SLO下承载并发。

主会话接下来讨论super-p95可迁移的双等待队列机制：哪些请求进入让行队列、让行队列的存量/工作量/时间预算、最低进展保护、GF或P侧放置，以及与FGJSQ＋batch级predictor的兼容。waiting重排、running/KV抢占和动态chunk尚未批准实施，本次不写调度补丁。

目前业务约定：64K的P90 TTFT<27s、P90 TPOT<30ms；128K为30s/40ms；32K为12s/32ms。正式指标沿用AISBench：客户端HTTP POST前记录起点、汇总器用首记录流式时间点计算TTFT；TPOT需沿用对应版本实际计算公式。B=16是整个3P3D集群的总施压并发，不能再乘3。历史发压的补发、间隔、限速方式仍应按其实际脚本核对，不因这个约定就假设所有历史run参数相同。

已有九字段报告只能证明长度/命中异质性，不能证明P90尾部来源。单位及completion语义仍未解决。0.7712次/s和约17.2K uncached token/s是选定UUID的处理起点画像，不是完成吞吐或容量。本次不要重新建立到达分布模型或拟合M/G/1。
