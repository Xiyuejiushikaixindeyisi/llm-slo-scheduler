FGJSQ09 / 35

用事件修正剩余工作量，再选择最低压力 P

FGJSQ = Fine-grained token Join Shortest Queue；批级时间预测用于负载衰减，不直接预测请求 TTFT。

scorep = Wp · (⌈Np / Mp⌉ + 1) / 2
wr(t) = Or · remainingr/Lr + Or · scheduledr/Lr · [1 − min(Δt / T̂batch, 0.95)]

W 随批事件和时间变化

W 是请求 committed load 的和；N 是未释放的 FG 请求数；M 是实例序列上限。未开始部分保留全额，本批 scheduled 部分随预测时间衰减。首个匹配事件把初始 O 校正为真实 prompt 长度 L。

派发是一次事务

rank 前重算 W；按 score 从小到大选可用 P；同锁完成候选检查与 native SHM CAS，成功后写 FG 预留。不能先按旧快照选中 P 再无条件占额。

实现对负载取整；预测无效时本批不衰减。5% retention 是 scheduled 负载估计的保留量，不是最低服务进展保障；score 不是秒，也不是精确剩余 token。g5 初估沿用请求 body bytes / 4。

比静态 token 账本细

静态账本直到释放前可能一直记 64K；事件驱动账本能感知已经推进的工作与在途 batch 的进度。

标签不是纯设备时间

异步队列空时，标签是提交到主机观察完成的区间；非空时可能是相邻主机观察结果的间隔。它既不是请求剩余 TTFT，也不等于孤立 kernel 耗时。

特征名字不等于物理含义

legacy cache_hit_rate 来自 prompt / computed 关系；computed 可在提交后提前推进。不能把它读成真实 APC 命中率，也不能从旧八维直接恢复新模型的 Σu² 与 Σuh。

单批效率优化有解析直觉，也有全局盲点

候选目标至少应区分“最高 Q/T”与“满足时间预算下推进最多 Q”。

吞吐代理

C* ∈ argmax Q(C) / T̂(C)

满预算 Q=C、固定成员与相对分配形状时，若 T(C)=a+bC+dC²，a,d>0，则内点效率最优 C*=√(a/d)。上下文影响线性项时，不直接改变该理想式的最优点，却影响时限可行域。

时限约束

max Q(C)　s.t. T̂(C) ≤ τ

τ 必须定义为 P 的批服务预算；不是直接取 30ms TPOT 或 30s TTFT。有限候选枚举还要满足 KV、序列、运行时硬预算与异步依赖。

逐批 Q/T 最优不等于整请求完成时间最优，更不保证总体 P90。把长 prefill 切开不会消除因果注意力总配对量；还可能增加固定批开销与历史 KV 重读。

正常因果计算下，完整长度 L、初始历史 h₀ 的总配对量为 h₀L+L(L+1)/2，与切块方式无关。真正影响性能的是硬件效率、重复成本、请求间执行机会与资源限制的组合。
